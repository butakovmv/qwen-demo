# Назначение проекта

Учебный проект для курса AI для разработчиков. Содержит простейший UI, обращающийся к API получения и записи вопросов и ответов.

# Структура проекта

## Особенности
- Монорепозиторий
- Мультимодульный проект
- Гексагональная архитектура
- Domain Driven Development

## Монорепозиторий

Все части проекта хранятся в одном репозитории, в соседних папках на верхнем уровне. Эти части можно разделить на несколько групп:
* информационные (документация, логи принятых решений, настройки деплоя),
* фронт,
* логика работы приложения,
* адаптеры (в терминах гексагональной архитектуры).

## Мультимодульный проект

- `docs/` - Документация по проекту
- `front/` - Пользовательский интерфейс на Vue и TypeScript
- `operation/` - Операции, которое может выполнять приложение. Содержит юнит-тесты операций.
- `app/` - Первичная точка входа, настройки Spring. Содержит тесты контекста приложения.
- `postgres/` - (позже) Адаптер к Postgres. Реализует интерфейсы источников данных. Содержит @DataR2dbcTest тесты
- `kafka/` - (позже) Адаптер к Kafka. Реализует интерфейсы источников данных
- `feign/` - (позже) Адаптер к HTTP-запросам на сторонние серверы. Реализует интерфейсы источников данных.
- `web-api/` - Адаптер HTTP API приложения. Реализует контроллеры, dto и мапперы, заботится об версионировании api. Обращается к интерфейсам вариантов использования. Содержит `@WebFluxTest` тесты на моках вариантов использования, тесты контролируют валидацию запросов, корректность кодов ответа, права доступа.

Каждый модуль-адаптер содержит внутри себя свои DTO, необходимые для работы с конкретным инструментом, а также мапперы между используемыми моделями предметной области и этими DTO.

## Domain Driven Development
В папке `docs/domain/` находятся папки, соответствующие доменным областям. Эти папки служат источником истины для проекта. В каждой из этих папок находится `Readme.md`, в котором описано назначение этой доменной области, перечислены ее сущности и операции (текстом и mermaid диаграммой последотвательности).

В модулях бэкенда в корневом пакете `miotaxi.aidemo` располагаются пакеты, соответствующие доменным областям. Пакеты соответствуют папкам в `docs/domain/`.

# Стек технологий

## Backend

| Технология  | Назначение |
|---|---|
| `Kotlin` | Основной язык |
| `Spring Boot`  | Фреймворк (WebFlux, Netty) |
| `Gradle (Kotlin DSL)` | Система сборки |
| `Spring WebFlux` | Реактивный HTTP |
| `Kotlin Coroutines` | Асинхронность (`suspend fun`) |
| `Jackson` | Сериализация JSON (`jackson-module-kotlin`) |
| `detekt` | Статический анализ Kotlin |
| `ktlint` | Форматирование Kotlin-кода |
| `spring-boot-starter-test` | Unit/интеграционные тесты |
| `reactor-test` | Тестирование реактивных потоков |

## Frontend

| Технология  | Назначение |
|---|---|
| `Vue 3` | Фреймворк (Composition API, `<script setup>`) |
| `TypeScript` | Типизированный JS |
| `Vite` | Сборка и dev-сервер |
| `vue-tsc` | Проверка типов Vue |
| `nginx`  | Раздача статики + proxy на backend |

| `ArchUnit` | Проверка архитектурных ограничений |
| `Vitest` | Тестирование фронтенда |
